# Legibility audit — supported paint grammar

- **Epic:** #1347 (`TSC-SF`)
- **Story:** TSC-SF1, #1357
- **Scope:** `src/adapter/legibility-audit.ts` only — `auditLegibility`,
  `resolveEffectiveBackdrop`, `ownTextColor`, and the rendered-ness/geometry
  helpers they call. Not a grammar for `pipeline.ts`'s own vendor-evidence
  Sensor (`scan()`), which has a distinct exclusion/inheritance model for a
  distinct purpose.

## Why this table exists

Every category below except the two marked **unknown** entered this module
because a reviewer found a live counterexample during `d36c575`/#1345's own
review (six "round N" cycles, one per counterexample) — not because a
category enumeration existed to check a new case against first. This table
is that enumeration, so the next gap is a designed table update, not another
incident-driven round. `legibility-audit.ts`'s own header points here.

Each row: **disposition** is `sound` (the check is exact, given its stated
boundary), `heuristic` (conservative and correct at the boundary it declares,
but not a general solution), or `unknown` (the category is not handled at
all — no test can pass or fail against it because no code path exists for
it). A `heuristic`/`unknown` disposition converging on `"underdetermined"`
is the intended, conservative outcome (Axiom C.1) — not a defect to later
"finish" into `sound` unless a bounded, provably sound extension is found.

Multiple tests may own one cell; a test may cover more than one cell (noted
where it does). Every test below lives in
`src/adapter/__tests__/legibility-audit.test.ts` unless stated otherwise.

## PG-GROUP — opacity, filter, blend mode, backdrop-filter (whole-element compositing)

Every category here except `PG-GROUP-BACKDROP-FILTER` composites the
_entire_ element (background, text, and descendants together) against
whatever sits behind it — a descendant's own opaque background cannot shield
it, unlike `PG-BG-IMAGE`'s ordinary z-order — and is checked all the way to
`document.documentElement` regardless of where color accumulation itself
resolves. `backdrop-filter` is a distinct mechanism (bot-found, Codex review
of this PR): it filters the backdrop _behind_ an element, before that
element's own background/content paints on top of the result — unlike
`filter`/`opacity`/`mix-blend-mode`, a nearer descendant's fully opaque
background genuinely _can_ shield an ancestor's `backdrop-filter` from
reaching anything further out. The code checks it via the identical
unconditional code path anyway, as a deliberate over-approximation for
implementation simplicity — see its own row below, not this paragraph, for
what it actually guarantees.

## PG-SCOPE — shadow roots, iframe/cross-realm boundaries

**Corrected finding (bot-found, Codex review of this PR):** `auditLegibility`
is invoked from exactly one production call site — `pipeline.ts`'s `fire()`,
which owns the _document_ scope only. `fire()`'s own `lastRoot` is typed
`Element` and is never a `ShadowRoot`. Shadow-scoped content has an entirely
separate sense→decide→realize path (`shadow-scope-theming.ts`'s
`projectOnce()`, which calls `pipeline.ts`'s `scan()`/`decide()` directly);
it never imports or calls `auditLegibility`/`decideLegibility`/
`realizeLegibility` at all — confirmed directly, a repo-wide search finds no
reference to any of the three outside `pipeline.ts` and this module's own
tests. **Shadow-scoped content is therefore never legibility-audited in
production, full stop — not `"underdetermined"`, simply never scanned.**
This is a materially larger gap than this table's own two `unknown` rows
below: those are silent within an _audited_ scope; this is an entire scope
class never entering the audit. Filed as #1370 (sub-issue of this story) for
a future story to wire or explicitly scope — fixing it is outside this
documentation-only PR.

The rows below are about what happens _inside_ one call to `auditLegibility`
against the document scope — the only scope this channel currently reaches
— not about `auditLegibility` itself crossing scope boundaries.

## Cross-cutting: verdict propagation (not a `PG-*` category)

`decideLegibility` and `realizeLegibility` do not test a paint-grammar
category — they test that any `"underdetermined"` value from _either_ the
foreground or backdrop channel propagates to an explicit
`{ verdict: "underdetermined" }` action (never silently resolved as
passing), and that the `data-sw-legibility` attribute realization is a
correct, idempotent, self-clearing projection of that decision. This is
Axiom C.1's conservative-verdict-propagation invariant, cross-cutting every
`PG-*` row above rather than owned by one of them.

Owning tests: "flags a violated pair below the WCAG AA minimum"; "emits
nothing for a pair at/above the WCAG AA minimum"; "flags underdetermined
backdrops rather than silently passing them"; "flags an underdetermined
foreground (e.g. an unparseable CSS Color 4 value) even with a fully
resolvable backdrop"; "MIN_CONTRAST_RATIO matches WCAG 2.1 AA normal text
(4.5:1)"; "composites a translucent own foreground over the backdrop before
measuring contrast"; "flags a near-invisible foreground as violated — it
composites toward the backdrop it sits on"; all four `realizeLegibility`
tests ("tags every element sharing a violated key"; the zero-write no-op
case; the stale-tag-clearing case; the unrelated-attribute-preservation
case).

## Coherence check

Every `PG-*` row above has exactly one declared disposition and at least one
evidence owner or an explicitly named gap (`G-1`). The two `unknown` rows
(`PG-GEN-PSEUDO`, `PG-SCOPE-IFRAME-CONTENT`) are the epic's two headline
findings; TSC-SF2 (#1358) is the story that changes their disposition, not
this one. `PG-GROUP-BACKDROP-FILTER` (structurally implemented but
untested) and `PG-SCOPE-SHADOW-HOST-TRAVERSAL` (structurally implemented but
currently unreachable in production — see the `PG-SCOPE` section header) are
recorded honestly rather than silently counted as covered by this table's
existence. `PG-BG-OPAQUE` and `PG-GEOM-RENDEREDNESS` were reclassified from
`sound` to `heuristic` during this PR's own Codex review (a `>= 0.999`
alpha-clamp cutoff, and unhandled `visibility: collapse`, respectively) —
neither produces a false `"legible"`, but neither is exact either. The
document-scope-only wiring gap this section's own header records is tracked
as #1370. Closing any of these five is outside TSC-SF1/#1357's own scope (a
documentation story), and none is claimed as done here.
